# PowerBI to StarRocks Runbook

Optional manual visualization guide. The six-step cleanup verifies the pipeline
through Gold SQL, not a completed Power BI Desktop refresh. Use synthetic local
data and the [current README](../../README.md); older client references are provenance.

## Purpose

Connect PowerBI Desktop on Windows to StarRocks through the MySQL protocol.

## Why This Path

PowerBI is the expected analyst-facing tool. StarRocks exposes a MySQL-compatible endpoint, so PowerBI does not need to understand Iceberg or MinIO directly.

Previous technology: dbt builds native StarRocks Gold tables from Iceberg Raw.

Next technology: PowerBI visualizes the Daily Operations Report and proves business usability.

## Connection Inputs

- Server: `localhost` for local Docker, or EC2 DNS/IP for remote POC.
- Port: `9030` unless changed.
- Database/catalog: `analytics`.
- Table: `gold_daily_operations_report`.
- User: `root` for local POC.
- Password: blank unless configured.
- Driver: MySQL-compatible connector supported by PowerBI Desktop.

Local connection string shape:

```text
Server: localhost:9030
Database: analytics
Username: root
Password: <blank for local POC>
```

## Local Windows Walkthrough

1. Confirm `health:iceberg` and `health:starrocks` pass from the repository root.
2. In Power BI Desktop, select **Get data > MySQL database**. Use server
   `localhost:9030`, database `analytics`, and Import mode.
3. Expand **Advanced options > SQL statement** and paste this small demonstration
   query. It does not depend on an old tagged row that may age out of Gold:

   ```sql
   SELECT order_number, destination_city, bank_status, record_type,
          champaines, serviceable_pincode, agent_name
   FROM analytics.gold_daily_operations_report
   ORDER BY order_number
   LIMIT 20;
   ```

4. Choose **Database** authentication, user `root`, and a blank password for this
   local POC. If asked about an unencrypted connection to this local endpoint,
   accept it. Load the result and add its columns to a Table visual.
5. Save the report. After a source update has reached Gold, use **Home > Refresh**
   and check that the city and status change in the visual. Import mode requires
   this refresh; Kafka arrival alone does not update the displayed report.

Microsoft documents the required Oracle MySQL Connector/NET package,
Database authentication, native SQL option and local unencrypted-connection
prompt in its [MySQL connector guide](https://learn.microsoft.com/en-us/power-query/connectors/mysql-database).
On this laptop the installed .NET provider was verified from **Windows PowerShell
5.1**, including a query of updated Gold values. PowerShell 7 uses a different
.NET runtime and does not show the same registered provider; that alone does not
mean Power BI's prerequisite is missing.

See the [2026-10-29 preflight evidence](../../notes/2026-10-29_final_walkthrough_preflight.md)
for what was tested and the remaining desktop UI check.

## Report Requirement

- Source: Gold `gold_daily_operations_report`.
- Grain: lead/order-level rows for drill-through.
- Filters: created OR updated date must be at least month start two months before today; the model also excludes the known test mobile numbers.
- Useful demo dimensions: `record_type`, `serviceable_pincode`, `champaines`, `state`, `agent_id`, `bank_id`.

Example query for validation before building the visual:

```sql
SELECT record_type, serviceable_pincode, COUNT(*) AS lead_count
FROM analytics.gold_daily_operations_report
GROUP BY record_type, serviceable_pincode
ORDER BY record_type, serviceable_pincode;
```

## Refresh Proof

1. Use a new synthetic report-relevant source lead in the local sample, preserving existing demonstration rows.
2. Wait for CDC, Kafka, Iceberg, Airflow/dbt, and StarRocks visibility.
3. Refresh PowerBI.
4. Confirm chart changes.
5. Save screenshot in `screenshots/`.

## Driver Issues to Record

- Driver name/version.
- Authentication behavior.
- TLS or non-TLS mode.
- Unsupported SQL generated by PowerBI.
- Refresh timing.

## Current POC Limitation

PowerBI Desktop is a manual Windows UI step. The repo can provide the StarRocks endpoint, table, query, and runbook, but the final chart screenshot must be captured from PowerBI Desktop.
